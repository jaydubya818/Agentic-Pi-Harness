# Changelog

All notable changes to Agentic-Pi-Harness. Versioning follows SemVer.

## [Unreleased]

### Added
- `scripts/check-secrets.mjs`, wired into `.husky/pre-commit` and exposed as `npm run check:secrets`: refuses to stage files that are credential material by definition (`*.pem`, `*.key`, `*.p12`, `id_rsa`, a real `.env`, `.npmrc`) or staged content carrying a self-identifying token (inline private key, GitHub PAT, Slack token, AWS access key id, provider API key, a literal `PI_HERMES_BRIDGE_TOKEN`). `docs/RISK-REGISTER.md` R11 has carried "no programmatic check exists" since v0.1.0 and lists this as its own top item. Deliberately no entropy heuristics — this repo commits sha256 digests, hash-chain `prevHash`es, and HMAC signatures constantly, and a guard that flags those gets disabled within a week.
- `GET /sessions` lists the adapter sessions the bridge is holding open (creation order, `?limit=N` tail), mirroring `GET /runs`. `POST /sessions` created them and `POST /sessions/:id/close` released them, but chasing a leaked idle session — or a 409 from close — previously meant reading the bridge state root off disk.
- `docs/ROADMAP.md` records the `2026-07-28` MCP specification constraints on the parked Tier C MCP-hosting surface (stateless core with no `initialize` handshake or `Mcp-Session-Id`, header-based routing, cacheable list results, DCR deprecated in favour of CIMD, Tasks moved to the `io.modelcontextprotocol/tasks` extension, Roots/Sampling/Logging deprecated), and states explicitly that the bridge's session-oriented control plane is a Pi-Hermes contract and not an MCP transport model.
- `GET /runs` lists run summaries (ids, status/state, terminal flag, failure class, links) in acceptance order, with the same `?limit=N` tail semantics as `GET /preflight-denials`. Operators previously had no way to enumerate runs over HTTP: execution ids had to come from out-of-band records or the bridge state root on disk.
- `GET /preflight-denials` accepts `?limit=N` to tail the N most recent denial records: the log is append-only and unbounded on a long-lived bridge, and the endpoint previously shipped the entire history on every poll. `limit` follows the same strict plain-decimal integer rule as the CLI flags.
- `AGENTS.md`: repo guidance for coding agents — commands, layout, and the fail-closed invariants (bridge auth, KB policy, persistence, golden freeze) a change must not weaken.
- `POST /sessions/:id/close` on the Hermes bridge closes the adapter session once its runs are terminal (409 while an execution is in flight, 404 for unknown ids). `runTaskViaBridge` releases its session best-effort after each governed run, so a long-lived shared bridge no longer accumulates one idle adapter session per run.

### Changed
- `compactHistory` serializes the event history once instead of twice: it called `shouldCompactHistory` (which `JSON.stringify`s the whole history to measure it) and then immediately recomputed the identical value for the record's `bytesBefore`. Compaction fires precisely when that history is at its largest, so the duplicate pass was paid on the biggest input the loop ever hands the function. `shouldCompactHistory` stays exported and unchanged for external callers.
- Readonly tool calls in a scheduled group now run through a bounded worker pool (8 in flight) instead of being dispatched all at once with `Promise.allSettled`. The size of a readonly group is model-controlled, so a turn emitting fifty parallel reads opened fifty file handles/sockets in the same tick — the path to EMFILE on Pi-class hardware. Start order, per-call execution, result collation order, and per-call rejection isolation are unchanged.
- `GET /preflight-denials?limit=N` no longer reads the whole append-only denial log to serve a tail: the limit is pushed into the state store, which reads backwards from the end of the file in growing windows until it holds enough complete lines, discarding the partial line at the front of the window. Unlimited reads are unchanged.
- Effect pre/post hashing streams each file through the digest instead of `readFile`-ing it whole, so the working set is O(chunk) rather than O(largest file touched) per mutating tool call.
- `stripAnsi` returns worker output lines untouched when they contain no backspace/DEL, instead of walking them character by character allocating a string per character. It runs on every output line and again over the whole retained transcript at exit; the scan measured ~30x faster on typical log lines.
- Pinned dev tooling bumped within its current majors: `@typescript-eslint` 8.59.0 → 8.67.0, `prettier` 3.8.1 → 3.9.6, `tsx` 4.21.0 → 4.23.12. `eslint` (8 → 10, flat config), `typescript` (5 → 7), `vitest` (3 → 4), `zod` (3 → 4), and `@types/node` (20 → 26) are each a breaking major and are deliberately left for their own change.
- The query loop's per-event trace append no longer issues a recursive `mkdir` for every traced event: the trace directory is identical for the whole session, so after the first line it was a pure syscall tax. Ensured directories are memoized (bounded, so a long-lived supervisor cannot accumulate paths forever) and a directory that disappears under a cached entry is re-created with the append retried once.
- The `?limit=N` tail parameter shared by `GET /preflight-denials`, `GET /runs`, and `GET /sessions` is parsed and validated in one place instead of once per endpoint.
- The sub-agent worktree helper bounds every `git` invocation (`worktree add`, `worktree remove`, `branch -D`) with a 120s SIGKILL timeout and a raised `maxBuffer`. A git that parks on a stale `index.lock` previously hung `createWorktree` forever — or, worse, `dispose()`, whose errors are swallowed, so the hang was silent and the worktree was never reclaimed.
- The query loop's per-event trace append no longer re-awaits dynamic `import()`s of `node:fs/promises` and `node:path` on every traced event; the modules are imported statically like the rest of the file.
- Direct dependencies are pinned to the exact versions already resolved in `package-lock.json` (caret ranges let a fresh install, or tooling that resolves from `package.json` instead of the lockfile, silently adopt whatever patch a registry serves that day). Nothing installed changes; future bumps become deliberate reviewed diffs per the supply-chain posture documented in the README.
- The legacy bridge path no longer rewrites `run.json` for every worker output line: each `task.output` event maps to status "running", so after the first line every persist was an identical full write+fsync+rename+dirsync cycle. It now persists only on status transitions, matching the redundant-persist fix the v2 path already received.
- The bridge state store and the tape recorder now reuse the shared collision-safe atomic-write primitive (`safeWriteFileAtomic`) instead of carrying their own copies of the write-tmp+fsync+rename+fsync(dir) dance.
- The bridge state store's `init()` skeleton mkdirs are memoized: every `persistSession`/`persistRun`/`appendRunEvent` re-ran both mkdirs, costing two redundant fs calls per worker output line on the per-event hot path. A failed init is not cached (later calls retry), and externally-wiped-root recovery is preserved by the per-record mkdirs that remain.
- The bridge no longer rewrites `run.json` twice per worker event: `handleV2AdapterEvent` and `transitionV2State` dropped trailing persists that duplicated the persist already performed by `emitV2Event`, halving the write+fsync+rename+dirsync traffic on chatty runs.

### Fixed
- A path-scoped `approve` rule matched a tool call if *any* of its paths were in scope. For `deny`/`ask` that is the correct fail-closed reading, but for `approve` it was a scoping escape: a `write_file` carrying `{ paths: ["tests/a.ts", "/etc/shadow"] }` matched a rule scoped to `tests/`, won first-match, and the out-of-scope path never reached the deny rule below it. Approve rules now require every path in the call to be in scope; a path-scoped rule still never matches a call with no extractable paths, so `every` cannot pass vacuously.
- `deleteKnowledgePath` denied Pi direct deletes of top-level `supervision/` but not of `missions/.../runs/.../supervision/`, even though `KB_ACCESS_POLICY_V1.md` lists both as Pi-only governance records. A run's review/approval/rejection lineage — the evidence a promotion decision rests on — could be unlinked outright instead of archived or tombstoned. `kb_mission_traces` remains deletable: the policy explicitly grants Pi authority to compact, summarize, or archive traces.
- `HermesBridgeServer.start()` passed only a success callback to `server.listen()`. A bind failure (EADDRINUSE from a second bridge or a stale process, EACCES on a privileged port) is reported by emitting `error` on the http server, and nothing listened for it — so Node turned it into an uncaught exception that killed the whole supervisor process while the promise `start()` awaited never settled. `start()` now rejects with the bind error and drops the half-built server so `stop()` stays a no-op and a retry is possible.
- The effect recorder collapsed every hashing failure onto the string `"absent"`. An EACCES, EIO, or a parent directory that vanished mid-call therefore produced a record asserting "no file existed here before or after this tool call" — a positive claim about the filesystem the harness could not actually make — and drove `binaryChanged`, so an unreadable text file was filed as a binary change. `absent` is now reserved for ENOENT/ENOTDIR and non-regular files; anything else records `unreadable` and emits a "could not be read" diff marker.
- `POST /sessions` allocated the adapter session (runtime dir, session slot) before persisting the bridge record, and a persist failure answered 500 without unwinding. Because the caller never receives the session id on that path, nothing could ever close it: the session and its runtime directory leaked for the life of the bridge. The `/sessions` counterpart to the existing `/execute` post-accept release now drops the record and best-effort closes the adapter session.
- `watchRun` drained one execution's events and then called `adapter.collect_result(session_id)`, which answers "whatever this session is doing now". The watcher yields on persisting every event — ample room for a queued `POST /execute` to accept the next run on the same session — and from that point collect_result returned run B's completion promise, so run A blocked on run B and was finalized with B's summary, artifacts, and status. `collect_result` now takes an optional `execution_id` and the bridge always passes it.
- Tool-output sanitization broke both of its documented invariants. `stripAnsi` only matched CSI sequences ending in `m`/`G`/`K`/`H`, so cursor moves, erase sequences, scroll regions, OSC hyperlinks/titles, and charset designations kept their parameter bytes: the control-char pass then deleted the lone ESC and left `[1A`, `[2J`, `]8;;https://...` in the prompt as literal attacker-chosen text. It now uses the same OSC/CSI/nF/Fe patterns `hermes/adapter.ts` applies to worker output, with Fe deliberately restricted to `@-Z \ -_` so the existing reassemble-then-escape behaviour for a split tag (`<pol\x1bicy>`) still holds. `stripControlChars` also omitted DEL and the C1 block, both of which keep the "invisible character splices a tag back together" hazard the C0 strip exists to close (`\u009b` is a single-byte CSI introducer).
- A failure between `spawnHermesTransport` returning and `send_task` returning its accepted envelope (a post-spawn event append, arming the timeout) fell into the catch path, which wrote a failed result and released the session but never touched the transport it had just spawned. The run was unsupervised from that point on -- `handleExit` returns early once `session.active` no longer points at the abandoned execution -- so the worker process tree kept running to completion with no timeout and no reaper. The catch now kills the transport and clears any armed timers before releasing the session.
- `promoteKnowledgeCandidate` validated the *lexical* class of its source path and then read the candidate with `readFile`, which follows symlinks. Candidates come from Hermes-writable zones (`docs/THREAT-MODEL.md` treats those as worker-controlled), so a symlink parked at an approved candidate path made promotion copy whatever it pointed at -- any file readable by the harness user -- into `knowledge/promoted`, `contracts/` or `standards/` stamped `trust: canonical` with fabricated approval lineage. The realpath class check the target and approval writes already get now also runs over the source before it is read.
- SSE fan-out runs inside the run's own event pump (`watchRun` -> `emitV2Event` -> `broadcastEvent`), all under `watchRun`'s try/catch/finally, so a subscriber write that threw -- a client whose socket died between its last `close` event and this write -- escaped into that catch and settled an otherwise healthy run as `execution_error` with a socket message as its failure reason. `closeSubscribers` had the same exposure from `watchRun`'s finally (where a throw replaces the run's real outcome) and `doStop`'s close loop made `server.stop()` reject, which the bridge CLI's shutdown handler turns into a non-zero exit mid-drain. A read-only observer can no longer change the outcome of the execution it watches: each delivery is isolated, logged, and the broken subscriber dropped.
- The bridge's run and session routers matched raw `URL.pathname` segments against maps keyed by the decoded id. `assertSafeStateIdSegment` only rejects path separators and NUL, so a caller-supplied v2 `execution_id` may legally contain a space, `#`, `?` or `%` -- all of which a client must percent-encode. The bridge accepted such a run with 202 and then answered 404 on `GET /runs/:id`, its events, and its SSE stream: a run it was actively supervising, with a persisted state directory and a live worker, was unreachable and uncancellable over HTTP for its whole budget. Segments are now decoded, falling back to the raw value so a malformed `%zz` path still 404s rather than throwing a `URIError` into the 500 handler.
- `normalizeRetryError` read `code`/`name`/`status` off the outermost error only. Every fetch-based provider on Node 18+ throws `TypeError: fetch failed` with the real socket error hung off `cause`, so the harness saw `{ code: null, name: "TypeError", status: null }`, classified the most common transient failure in production as `model_open_fail_closed`, and never retried -- the retry state machine effectively only fired for hand-rolled providers that set `code` directly. It now walks the cause chain (bounded depth, cycle-guarded) for any field the outer error lacks, and recognises undici's spellings of the transport codes already on the allowlist (`UND_ERR_CONNECT_TIMEOUT`, `UND_ERR_HEADERS_TIMEOUT`, `UND_ERR_SOCKET`).
- `estimateTokens` floored every input at 1 token, including the empty string, while `piDevProvider.normalize()` deliberately maps each contentless housekeeping chunk a real provider emits (`content_block_stop`, `message_delta`, `ping`) to an empty text delta. Every one of them was charged an output token, so the `CostRecord` the harness persists as run evidence overstated tokens and USD by an amount that scaled with stream chattiness rather than with real output. Empty chunks now cost nothing; the min-1 floor still applies to anything carrying text.
- `readTailLines` issued one `handle.read()` per window and decoded the whole buffer regardless of how many bytes landed. `read()` may return short even for a regular file, and the untouched zero fill decodes as NUL padding appended to the newest record -- so the last line stopped being valid JSON and the most recent preflight denial, the one an operator polling `?limit=N` is looking for, was dropped by the parse loop. The window is now filled with a read loop and only the bytes read are decoded.
- `pi-harness run` pushed every non-`--trace` argument into its positional list, so a mistyped flag (`--trcae=/x`) became the workdir and the golden path ran against a directory of that literal name, reporting success. `--trace=` with an empty value was the same silent failure in the other direction: the loop only writes a trace when the path is truthy, so tracing was quietly disabled. The CLI now applies the same terminal flag guard the hermes CLIs use, rejects an empty `--trace=`, and rejects a third positional argument.
- A tape whose records were re-chained after editing verified as clean: `verifyTapeRecords` only checked that line 1 was a header and that each record hashed onto the previous one, and the chain is recomputable by anyone holding the file. Two sessions concatenated and re-chained therefore passed as one tape, and events could be renumbered undetected. Verification now also asserts the writer's structural invariants — only line 1 may be a header, and each event's `seq` must equal its line index.
- The query loop abandoned the model stream's async iterator on both the retry path and the fail-closed path without calling `return()` on it, so the provider-side generator's `finally` never ran and the socket behind the abandoned stream stayed open for the life of the process. Both paths now release the iterator (best-effort) before retrying or throwing.
- `snapshotPre` retained the full text of every file a mutating tool touched for the life of the tool call, and `capturePost` read the post-image alongside it, so rewriting one large file put two full copies on the heap — even though the LCS budget already refused to diff anything near that size. Files past an 8 MiB budget are no longer read for diffing and report the same "diff omitted" marker the LCS budget uses; `binaryChanged` stays reserved for genuinely binary content.
- `detectArtifacts` walked the worker's output directory with no bound on depth or count, and that directory is worker-written (untrusted per `docs/THREAT-MODEL.md`). Every file found becomes an artifact record that is hashed, embedded in the result envelope, persisted, and shipped over HTTP, so a worker dumping a dependency tree turned run finalization into unbounded work. Depth is now capped at 24 and artifacts at 5000, with directory entries sorted so a truncated set is deterministic rather than filesystem-order dependent.
- The bridge HTTP server ran on Node's default receive timeouts (60s of header silence, 300s to dribble a body), letting a slow or wedged client park connections on a long-lived loopback service. `headersTimeout`/`requestTimeout`/`keepAliveTimeout` are now bounded; `requestTimeout` covers request receipt only, so long-lived SSE event streams are unaffected.
- The shell-contract hook executor decoded each stdout/stderr chunk with a per-chunk `toString("utf8")`. A pipe read can split a multi-byte UTF-8 character across two `data` events, so every half became U+FFFD: a hook whose `reason`/`patch` contained any non-ASCII text came back corrupted, and could fail `JSON.parse` outright and surface as a bogus "shell hook produced invalid JSON" error. Both streams now carry partial bytes over with a `StringDecoder`, matching `hermes/transport.ts`.
- `runTaskViaBridge`'s two setup requests (`POST /sessions`, `POST /execute`) ran with no abort signal at all, unlike every poll/cancel/cleanup request around them. A bridge that accepted the connection and never answered parked the whole governed run on undici's ~300s header default before the deadline loop had even started. Both are now bounded by `pollSettings.setupRequestTimeoutMs` (30s — looser than the poll timeout, since a cold worker spawn is legitimately slower than a status poll).
- `detectHermesRepoPath` reported a *regular file* named `hermes-agent` (or a `HERMES_REPO_PATH` pointing at one) as the worker repo root, because `accessSync(path, R_OK)` succeeds for files. It now requires a directory, mirroring the `isFile()` guard `detectHermesBinaryPath` already applies.
- The LaunchAgent setup script emitted a run script that interpolated `$REPO_ROOT`, `$STATE_ROOT`, and `$TOKEN_FILE` unquoted, so any of those paths containing a space word-split at launch time and the agent failed to start with a confusing `cd`/`cat` error. The generated script now quotes them, and the bridge token file is explicitly `chmod 600`'d — `umask 077` only constrains newly created files, so re-running left an already-loose token file world-readable.
- The `hermes-bridge` CLI's SIGINT/SIGTERM handlers awaited `server.stop()` inside a void'd async closure, so a stop that rejects escaped the signal handler as an unhandledRejection and crashed the process mid-shutdown. The handler now settles the stop explicitly: exit 0 on success, log and exit 1 on failure.
- `runHermesSupervisorTask` rewrote the session-start provenance manifest after the governed run completed -- byte-identical to the one `runTaskViaBridge` writes before the run begins, except for stamping a post-run `createdAt` over the genuine start time -- and paid a second write+fsync+rename+dirsync cycle for it. The start-time record now stands.
- A long-lived Hermes adapter session retained every task event of every execution it ever ran in memory -- one `task.output` event per worker output line -- so a bridge session running many chatty governed tasks grew the harness heap without bound, the same way the raw-output and partial-line buffers did before their caps. The oldest events are now trimmed past `maxRetainedSessionEvents` (default 10k); each execution's full history still lands in its on-disk `events.jsonl`. `read_events` tracks an absolute cursor so trimming cannot shift events under a paused reader, and remembers terminal execution ids so a late reader of a fully-trimmed execution returns instead of parking forever on a waiter nothing wakes.
- A bridge that accepted the TCP connection but never answered (wedged process, half-dead proxy) parked each of `runTaskViaBridge`'s poll requests on undici's ~300s default timeout, stalling the loop far past the run deadline it exists to enforce -- and the deadline-expiry cancel, settle wait, event capture, and session close could each hang the same way afterwards. Every poll/settle/cleanup request now carries an `AbortSignal.timeout` (`pollSettings.requestTimeoutMs`, 10s), keeping deadline overshoot bounded.
- Every `hermes-doctor` bridge probe (healthz, meta, session create, execute, run polls, cancel, settle wait, events, session close) was an unbounded fetch with the same failure mode: a wedged bridge parked the probe for minutes instead of failing the check. All probes now abort on `requestTimeoutMs` (default 10s) and settle as failing checks promptly.
- A bridge failure *after* the adapter accepted a task (a `run.json` persist error, a structured-event emit failure) was answered as a 400 preflight denial — with a bogus denial record — while the already-spawned worker kept running with nothing supervising it: the phantom run record stayed "accepted" forever, wedging the session (close answers 409) and the execution id. Post-accept failures now best-effort cancel the worker, drop the phantom record, and answer 500 without a denial record, on both the legacy and v2 paths.
- The Hermes adapter's partial-line buffer grew without bound when a worker streamed one enormous line with no newline, defeating the `maxRetainedOutputChars` retention cap that already protects the raw-output buffer. The partial line now keeps only its tail (the full stream still lands in `hermes.raw.log` on disk).
- `POST /cancel` answers 202 before the run actually settles, so `runTaskViaBridge`'s deadline-expiry cancel raced its own session close: a real bridge answered 409 (non-terminal execution) and the adapter session leaked on an external long-lived bridge, while the thrown error reported a stale "running" status. The client now waits (bounded, `cancelSettleMs`) for the terminal record; a run that settles with a result payload is returned like any other terminal run. `hermes-doctor` had the same race — plus deleting its smoke output directory out from under the still-writing worker — and now performs the same bounded settle wait, reporting the settled status in the smoke check.
- When its poll deadline expired with the smoke execution still running, `hermes-doctor` went straight to cleanup: the session close answered 409 (non-terminal execution) — reintroducing the idle-session leak the close exists to prevent — and the doctor deleted its smoke output directory out from under the still-writing worker. The doctor now posts a best-effort `/cancel` first, mirroring the deadline-expiry cancel `runTaskViaBridge` performs.
- `hermes-smoke` and `hermes-demo` started a direct `HermesAdapter` session and exited without ever closing it, so the persisted `session.json` never read `closed` and, on failure paths, a still-running detached worker survived process exit as an orphan (`close_session` cancels it). Both dev-only CLIs now release the session in a `finally`, matching the cleanup `hermes-doctor` and `runTaskViaBridge` already perform.
- `safeWriteJson` used one fixed tmp name (`path + ".tmp"`) for every write, so two concurrent writers to the same target truncated each other's tmp file mid-fsync — the winner could rename a torn file into place and the loser's rename threw ENOENT after the shared tmp was moved away. Every write now gets a unique tmp name (atomic, last-write-wins) and a failed write unlinks its own tmp instead of leaving orphans.
- When the poll deadline expired with a governed run still executing, `runTaskViaBridge` threw and walked away while an external long-lived bridge kept running the task (default budget 900s) with nobody collecting it. The client now posts a best-effort `/cancel` before surfacing the missing-result error; embedded bridges were already cancelled by `server.stop()`.
- `runQueryLoop` declared `counters` / `costTable` inputs (and `metrics/otel.ts` documents passing a `FanOutCounters` sink), but both were typed `unknown` and silently ignored: a caller-supplied metrics sink never saw an increment and `LoopResult.cost` was hardcoded `null` despite `CostTracker` existing and being tested. The loop now increments the provided `CountersSink` in real time and, when a `CostTable` is supplied, returns a `CostRecord` estimated from the emitted event stream.
- `runTaskViaBridge` wrote the governed run's `request.json` and `result.json` with a bare `writeFile`, leaving the run's source-of-truth records exempt from the write-rename+fsync invariant; a crash mid-write could leave torn JSON. Both now route through `safeWriteJson`, as do the golden-path `metrics.json` and the external-validation `summary.json`.
- The pi.dev chunk normalizer threw `E_MODEL_ADAPTER` for any chunk type outside the four it mapped, but the Anthropic-style stream family it mirrors also emits `content_block_stop` after every block, `message_delta` before `message_stop`, and keepalive `ping`s — so a real provider-backed run died mid-stream on the first content block. Those housekeeping chunks now map to a contentless text chunk; genuinely unknown types still fail closed.
- A second concurrent `HermesBridgeServer.stop()` — e.g. a second SIGINT while the CLI shutdown handler was still draining watchers — re-entered the teardown and called `server.close()` on an already-closing server, rejecting with `ERR_SERVER_NOT_RUNNING` out of an unawaited signal handler and crashing the process mid-shutdown. Concurrent stops now join the in-flight stop promise; a failed stop stays retryable.
- `hermes-doctor` created a bridge session for its execute smoke test and never released it, so every doctor run against a long-lived bridge left one idle adapter session behind. The doctor now closes its session best-effort in cleanup, matching the release `runTaskViaBridge` performs after governed runs.
- Contract V2 result envelopes, artifact manifests, and traces were written with a bare `writeFile`, the one persistence path still exempt from the write-rename+fsync invariant; a crash mid-finalize could leave a torn half-written `result.json`. `writeJsonArtifact` now routes through `safeWriteJson`.
- `pi-harness hermes-bridge --port` still accepted hex (`0x1f90`) and exponent (`8e3`) spellings via bare `Number()` after the other numeric flags moved to the strict plain-decimal rule; it now uses the shared `parseIntFlag` helper.
- The subprocess and script PTY transports settled worker exit on the child's `exit` event, which Node can emit while the final stdout/stderr chunks are still queued in the pipes. The adapter parses the structured `PI_TASK_RESULT_JSON` block and the session footer from the output tail at exit settlement, so a late-flushed result block could be silently lost — downgrading a successful run to `structured_output: false` (a `contract_error` under the v2 finalize path) and dropping session resumption. Exit now settles on `close` (both pipes drained), with a bounded drain grace after `exit` so a worker-spawned descendant holding the inherited pipes open cannot park settlement behind an orphaned background process.
- Every CLI entrypoint guarded execution with `import.meta.url === \`file://${process.argv[1]}\``, which is false whenever the two spellings differ: a clone path containing a space (or any URL-escaped character) and a symlinked entrypoint -- notably the packaged `kb` bin stub npm installs into `node_modules/.bin` -- both made the CLI exit 0 having silently done nothing. A shared `isCliEntrypoint()` helper now falls back to comparing against `pathToFileURL(realpathSync(argv[1]))`, covering both.
- `pi-harness doctor` read `.tool-versions`, `package.json`, and the canonical golden tape relative to the current directory, so running it from anywhere but the repo root failed 3 of its 4 checks with misleading output. Checks are now anchored at the package root derived from the module location.
- Numeric CLI flags accepted hex (`0x10`), exponent (`1e3`), and float (`5.0`) spellings via bare `Number()` while every error message promises "an integer"; a typo like `--timeout 0x10` silently started a run with a surprising value. Only the plain decimal spelling parses now.
- `promoteKnowledgeCandidate` accepted arbitrary source, target, and approval paths, so a misdirected promotion could mint `trust: canonical` content from a file outside every governed zone or write canonical output (and its approval record) anywhere on disk. The KB_ACCESS_POLICY_V1 promotion rule is now enforced: sources must come from a candidate zone (wiki, `queues/discovery`, `handoffs/inbound`, mission outputs, `staging/normalized`), targets must land in a canonical Pi-only directory (`knowledge/promoted`, `contracts`, `standards`), and the approval record must live under `supervision/`. Violations deny with an audited `kb.write_denied` event. `createKnowledgeTombstone` is likewise constrained: tombstones must land under `archive/` or `supervision/`.
- `setup-hermes-bridge-launchagent.sh --dry-run` echoed the bridge bearer token to stdout; with an existing `~/.pi/hermes-bridge-token` that leaked the live token into terminals and shell logs. The dry run now reports whether a token will be reused or generated without printing it.
- Contract V2 artifact finalization aborted entirely when an expected artifact path existed but was not a readable regular file: a directory (or unreadable file) at the path passed the bare `stat()` existence check and then threw EISDIR/EACCES out of `readFile` mid-finalize, settling the run as a generic `execution_error` with no result envelope or manifest written at all. Finalization now only accepts regular files -- a required artifact that is a directory reports `artifact_error` ("required artifact missing or not a regular file") -- and a read failure during frontmatter validation or manifest computation classifies the run as `artifact_error` while still producing the full contract result envelope.
- KB write policy classified paths lexically, so a symlink component could make an approved-looking path physically resolve outside the knowledge roots (or into a governed class) — a Hermes write to `~/My LLM Wiki/<symlink-to-outside>/x.md` landed outside every approved root while auditing as an allowed `wiki` write. Writes now re-classify the realpath of both roots and target before writing; benign parent symlinks (e.g. `/tmp` -> `/private/tmp`) stay neutral, boundary-crossing symlinks are denied and audited via `kb.write_denied`. `deleteKnowledgePath` had the same hole (`unlink` follows intermediate symlinks), so a Hermes wiki delete through a symlinked directory could remove a file outside the roots; the same guard now runs before any unlink and denies via `kb.delete_denied`.
- `ReplayRecorder.writeEvent` advanced the in-memory hash chain before the append+fsync, so one failed append (ENOSPC, EIO) made every later successful write chain off a hash that never landed on disk, failing tape verification from that line on. The chain now only advances once the record is durable.
- The hermes-demo/run/smoke/bridge/doctor flag loops silently ignored unknown flags and known flags missing their trailing value, so a typo (`--objectve`, `--outputdir`) or a forgotten value (`--objective` as the last argument) started a long governed run with default settings instead of failing at the command line. A shared `assertKnownFlag` guard now rejects both; acceptance-hermes forwards its wrapper-only flags via an explicit tolerate list.
- The standalone `inspect` CLI runner had no rejection handler, so a missing or corrupt policy log surfaced as an unhandledRejection stack trace instead of the `FAIL:` + exit 1 contract the other thin shells follow.
- `writeKnowledgeJson` skipped required-frontmatter validation entirely, so routing a governed `.md` KB artifact through the JSON writer bypassed the enforcement `writeKnowledgeText` applies. The JSON writer now fails closed on frontmatter-required paths and emits `kb.frontmatter_validation_failed`.
- `runTaskViaBridge` polled a terminal run for the *full* task deadline (default ~900s) when the run ended with an error but no result payload — spawn failure, torn transport, or bridge-restart reconciliation — before failing with a message that omitted the recorded error. Terminal errored runs without a result now settle immediately, and the thrown error carries the run's status and error.
- `hermes-doctor` crashed with a raw fetch error when the bridge was down (connection refused) or fronted by a proxy returning non-JSON, losing the checks it had already gathered. An unreachable bridge is now reported as a failing `bridge healthz reachable` check, and the doctor stops there instead of issuing more requests that would crash the same way. One flaky `/runs` poll during the smoke test likewise no longer aborts the doctor mid-run.
- Numeric CLI flags across the Hermes shells were parsed with bare `Number()`: `--timeout abc` (hermes-run/smoke/demo), `--timeout-ms abc` (hermes-doctor), and `--port 70000` (acceptance-hermes) flowed NaN or out-of-range values into schema-validated requests and failed deep inside a run with an opaque zod error or a NaN poll deadline. They are now validated at the command line with the same clean error the bridge's `--port` already used.
- One torn line in a run's persisted `events.jsonl` (crash mid-append) no longer discards every other event for that run when the bridge reloads state; corrupt lines are skipped individually, matching the preflight-denials log behavior.
- A spawn-phase `send_task` failure emitted its terminal `task.failed` event only after the active execution was cleared, so the event was delivered to in-memory watchers but never appended to the run's on-disk `events.jsonl` — the persisted log showed `task.started` with no terminal record. The terminal event is now persisted before the execution is released, matching normal-exit ordering.
- KB frontmatter validation only matched LF-delimited fences: a worker-produced markdown artifact with CRLF line endings was denied as "required frontmatter missing" despite valid frontmatter, and promotion left the stale fence in the promoted content. CRLF is now accepted and values no longer retain a trailing carriage return.
- Artifact auto-detection wrapped its whole recursive walk in one try/catch, so a single unreadable output subdirectory threw away every artifact already collected from readable directories; only the unreadable directory is skipped now.
- A single failed supervisor heartbeat emit permanently disabled the stuck-run watchdog (both timers shared one `stopped` flag), and a stuck-run cancel that threw (session/worker already gone) skipped the terminal settlement, leaving a hung run non-terminal forever. Heartbeat emit failures are now logged and non-fatal, and a failed cancel still settles the run as `stuck_run`.
- The Hermes session footer parser matched the *first* `session_id: <x>` occurrence anywhere in worker output, even mid-line; any output that mentioned "session_id:" was captured and silently passed to `--resume` on the next task, hijacking session resumption. Only a full trailing `session_id: <id>` line counts now, and the last one wins.
- `/execute` accepted duplicate caller-supplied `execution_id` values, silently replacing the existing run record in the bridge's run map and interleaving the new run's persisted events with the old run's log. Duplicates now fail preflight with a 400 and a persisted preflight denial on both the v2 and legacy paths.
- The subprocess transport child shared the harness's process group, so `killChild`'s POSIX group kill hit ESRCH and only the direct child died — descendants spawned by the worker survived cancel/timeout as orphans. The child is now spawned detached (matching the script pty transport), making the group kill reap the whole worker tree.
- A failure while finalizing an exited run (result write, event-log append) escaped `handleExit`'s bare `void` call as an unhandledRejection — terminating the harness — while the completion promise never settled and the session stayed active forever. Finalization failures now log, emit a best-effort terminal `task.failed` event, release the session, and reject the completion so `collect_result` sees the real error.
- `POST /sessions` accepted any `env` shape: a string spread its indexed characters into the worker environment and an array spread its elements, silently corrupting the spawn env. Non-object `env`, non-string env values, and non-string/empty `profile` now return 400.
- `classifyKnowledgePath` missed the `.markdown` extension, so knowledge writes with that extension skipped required-frontmatter validation everywhere the classifier gates it.
- `pi-harness hermes-bridge --port abc` (NaN) and out-of-range ports passed straight to `server.listen`; ports are now validated as integers in 0-65535 with a clean argument error.
- The `run.ts` CLI entrypoint had no rejection handler; failures crashed via unhandledRejection instead of printing the error and exiting 1 like the other entrypoints.
- Worker command resolution no longer accepts directories: `accessSync(X_OK)` passes for directories (searchable), so a PATH entry containing a directory named like the command — or a directory at `HERMES_COMMAND` / `~/.local/bin/hermes` — was resolved as the binary and failed at spawn with a confusing error. An empty command also resolved to the first searchable PATH directory itself (`join(dir, "") === dir`). Both the transport's PATH lookup and Hermes discovery now require a regular file.
- A spawn-phase `send_task` failure rejected the execution's completion promise with no consumer attached, which Node reports as an unhandledRejection and terminates the harness; it also never emitted a terminal event, so `read_events` watchers keyed to a caller-supplied execution_id parked forever. The failure path now emits `task.failed`, marks the rejection handled, and still rethrows.
- An approval requester that rejects *after* losing the timeout race (typically in response to the abort signal sent on timeout) no longer surfaces as an unhandledRejection; a requester that throws synchronously now fails closed to a system deny instead of escaping `requestApprovalDecision`.
- A mutating tool that threw leaked its `EffectScope` (full pre-snapshot text of every touched file) in the recorder's scope map for the life of the session; the query loop now discards the scope on the tool-error path. The back-compat default scope is likewise released once `capturePost` consumes it instead of accumulating (and potentially reusing) stale pre-state.
- Contract V2 artifact manifest items report `size_bytes` for the exact bytes that were hashed instead of a separate `stat()` snapshot, so a concurrent rewrite can no longer produce a manifest whose sha256 and size describe different file states.
- `assertSafeStateIdSegment` rejects empty ids: an empty execution_id mapped the run directory onto the bridge state `runs/` root itself, and an empty session_id persisted to `sessions/.json`.
- Policy `path` / `pathPrefix` matching normalizes paths before comparison: aliased spellings of a denied location (`./secrets/key`, `secrets//key`) no longer dodge a deny rule, and traversal segments (`tests/../secrets/key`) can no longer ride an approve prefix rule out of its subtree. Paths still pointing above the root after normalization (`../x`) never match a prefix rule.
- The tool-output sanitizer strips control characters *before* escaping nested `<system>`/`<policy>`/`<tool_output>` tags; previously `<sys\x00tem>` passed the escape pass untouched and reassembled into a live `<system>` tag once the NUL (or a stray ESC) was removed.
- An approval requester that throws (crashed approval UI, dropped bridge connection) fails closed to a system deny with the failure reason instead of aborting the whole query loop.
- Tools that throw non-Error values no longer produce `tool error: undefined`; the thrown value is stringified into the tool_result.
- `runTaskViaBridge` reads the `/execute` body as text before parsing, so a non-JSON error response (auth rejection, proxy HTML) surfaces its HTTP status and body instead of an opaque JSON parse error.

### Security
- Dev-dependency advisories resolved via `npm audit fix`: js-yaml 4.3.1 (CVE-2026-59870, quadratic CPU in `!!omap` resolution) and nanoid 3.3.18 (GHSA-2v37-7h3g-55p8, custom generators loop forever at size 0). Because both patched tarballs were published inside the Aug 2026 npm supply-chain-worm window, they were manually inspected before adoption: no install scripts, no network/exec/credential-access code.
- The Hermes bridge refuses to start unauthenticated on a non-loopback host. `/sessions` and `/execute` let callers spawn worker processes with a caller-chosen workdir and environment, so `pi-harness hermes-bridge --host 0.0.0.0` without `--auth-token` / `PI_HERMES_BRIDGE_TOKEN` was unauthenticated remote command execution on every interface (the dominant 2026 MCP-ecosystem CVE pattern). Loopback spellings (`127.0.0.0/8`, `::1`, `::ffff:127.x`, `localhost`) stay usable without a token.
- Shell hooks are untrusted executables, but `runShellHook` spawned them with the harness's full `process.env` — leaking `ANTHROPIC_API_KEY`, `AWS_*`, and any other secret into hook processes, contrary to contract item 6 in docs/HOOK-SECURITY.md. Hooks now receive only `PATH`, `HOME`, `PI_HOOK_EVENT`, `PI_SESSION_ID`, and manifest-declared env entries; the doc's env-leak review-checklist test is now in the suite.
- Shell hooks also inherited the harness working directory, so a hook could read session files (`./policy.jsonl`, tapes) via relative paths despite contract item 5 requiring a scratch dir. Each invocation now runs in a private `mkdtemp` directory that is removed when the hook settles.
- Dev-dependency brace-expansion DoS advisories (GHSA-mh99-v99m-4gvg, GHSA-rgw5-rvv9-x895) resolved via `npm audit fix`.
- esbuild forced to 0.28.1 via an `overrides` entry for GHSA-g7r4-m6w7-qqqr (dev-server arbitrary file read on Windows; dev-dep only). `npm audit fix` could not apply it because tsx and vite pin ranges below the patched version.
- Dev-dependency advisories resolved via `npm audit fix`: vitest 3.2.7 (critical — arbitrary file read/execute via the UI server, GHSA-5xrq-8626-4rwp), plus brace-expansion, js-yaml, and postcss DoS/file-read advisories. Remaining findings sit behind the pinned eslint 8 toolchain.

- The `script(1)` PTY transport passed BSD-style arguments on every platform; util-linux `script` ignores extra positional arguments, so on Linux it spawned an interactive shell, never ran the worker command, and reported exit 0 with empty output. Linux now uses `script -qefc '<quoted command>' /dev/null` (exit code propagated, output flushed); BSD/macOS behavior is unchanged.
- `POST /cancel` and `POST /interrupt` resolved the execution to a run but then signalled the run's *session*, i.e. whatever execution is currently active on it. Cancelling an already-finished run could SIGTERM an unrelated execution reusing the session. Terminal runs now return 409, and `adapter.cancel`/`interrupt` accept an execution id and no-op on mismatch.
- Worker timeouts are classified as v2 state `timed_out` / failure class `timeout` instead of `execution_error` (or `contract_error` when the SIGTERM'd worker never printed its structured result block). `HermesTaskResult` and the terminal adapter event carry a `timed_out` flag.
- Runs restored from bridge state after a restart no longer report `accepted`/`running` forever; with the worker process dead alongside the old bridge, they are marked failed (`transport_error` for v2 runs) with an explicit bridge-restart error.
- `HermesBridgeServer.stop()` cancels in-flight executions before draining watchers instead of blocking shutdown until the worker finished or hit its timeout budget (900s default).
- Policy `pathPrefix` rules are segment-aware: `"tests"` no longer matches `tests-evil/x.ts` or `tests.bak`, closing an approve-rule leak onto sibling paths sharing leading characters.
- A stale cancel force-kill timer could SIGKILL the *next* execution on the same session: the timer re-read `session.active` when it fired, and a double cancel (or the timeout path) orphaned the previous timer so exit cleanup never cleared it. The timer now captures the execution being cancelled and pending force-kill timers are cleared before a new one is armed.
- `read_events` iterators no longer hang forever when their session is closed mid-iteration; closed sessions set a flag that drained generators observe instead of re-parking on a waiter nothing can wake.
- Raw worker output retained in memory for end-of-run parsing is capped at an 8M-char tail (configurable via `maxRetainedOutputChars`); the full stream still lands in `hermes.raw.log`. Previously a chatty long-running worker grew the harness heap without bound.
- `POST /sessions` with a missing or empty `workdir` returns 400 instead of reaching `start_session(undefined)` and surfacing as an unhandled 500; `/interrupt` and `/cancel` now reject non-string `execution_id` bodies with 400.
- v2 result envelopes' `logs_ref.bridge_state_root` pointed at the hardcoded default `~/.pi/hermes-bridge-state` even when the bridge ran with a custom `stateRoot`; the configured root is now threaded through.
- Sub-agent slugs are allowlisted before they become filesystem path segments and `pi/<slug>-<ts>` branch names; traversal (`../evil`), nested (`a/b`), and git-ref-syntax slugs are rejected, and the worktree base check is boundary-safe instead of a raw `startsWith`.
- A missing or non-executable Hermes command no longer crashes the harness with an unhandled `'error'` event from the spawned child; both stdio transports surface spawn failures as a single exit event with code 127.
- The shell hook hard timeout now SIGKILLs the hook's whole process group (POSIX), so hung descendants die with the hook as the contract comment always promised; shell hook stdout/stderr capture is bounded at 4MB per stream.
- `runTaskViaBridge` no longer aborts a still-executing governed run because one `/runs` poll returned a non-2xx or non-JSON response; polls retry until the deadline and raw event capture is best-effort once the result exists.
- The effect recorder caps its LCS diff at a 4M-cell budget; a rewrite of a huge text file records pre/post hashes plus a `[diff omitted]` marker instead of allocating an O(n·m) table that could OOM the harness.
- Transport output is decoded with a per-stream `StringDecoder`, so a multi-byte UTF-8 character split across pipe reads no longer reaches the adapter as U+FFFD replacement characters.
- Hook timeout races (`hooks/dispatcher.ts`, `hooks/mediation.ts`) clear the losing timer instead of keeping the event loop alive for up to `timeoutMs` per hook call, and a hook that rejects after losing the race no longer surfaces as an unhandled rejection.
- Worker-mode `allowedWritePathPrefixes` matching is now normalized and boundary-aware: sibling directories sharing a string prefix (`sandbox-evil/` vs `sandbox`) and traversal escapes (`sandbox/../src/x`) are denied.
- Client-supplied `execution_id` values are preflight-denied by `/execute` unless they are safe single path segments; the bridge state store also refuses unsafe session/execution segments, closing a path traversal out of the state root.
- One corrupt line in `preflight-denials.jsonl` (e.g. a crash mid-append) no longer makes `loadPreflightDenials` silently return an empty list; corrupt lines are skipped individually.
- Create-mode knowledge writes open with `O_EXCL` (`wx`), so a file that appears between the policy existence check and the write fails with `EEXIST` instead of silently overwriting create-only queue items, traces, or immutable requests.

- Trace files can no longer be truncated by an explicit create-mode write to an existing append-only trace path; the write now fails closed with `kb.trace_overwrite_denied`.
- Knowledge-root containment no longer misclassifies legal dot-dot-prefixed names (e.g. `..weird.md`) directly under a root as outside it.
- Stuck-run detection compares against the last observed worker progress/output event instead of the supervisor's own emitted heartbeats. Previously a hung worker was never flagged with heartbeats enabled (the default), and every run older than `stuckTimeoutMs` was killed with them disabled even while actively streaming.
- Shell hooks that exit before reading their stdin payload no longer crash the harness with an unhandled `EPIPE`; the hook promise settles from exit code + stdout as intended.
- `wrapToolOutput` escapes quote/angle-bracket characters in the `tool` and `id` attributes so a hostile tool identity cannot break out of the untrusted `tool_output` envelope or forge `trusted="true"`.
- `runTaskViaBridge` checks the `/sessions` HTTP status and fails fast with the response body instead of surfacing a missing `session_id` later as an unrelated error.
- Hermes adapter output chunks are handled strictly in order (serialized per execution); concurrent chunk handlers could previously interleave raw-log appends and reconstruct line boundaries out of order.
- Hermes deletes outside both knowledge roots are now denied (previously fell through every guard to an unconditional `unlink`).
- Append-mode knowledge writes use a true `O_APPEND` append instead of read-whole-file + truncate-and-rewrite, so a crash mid-append can no longer lose an entire trace.
- `promoteKnowledgeCandidate` fails fast if the canonical target or approval record already exists instead of silently overwriting promoted knowledge.
- `writeKnowledgeJson` emits `kb.queue_create` for queue creates, matching `writeKnowledgeText` in the policy audit stream.
- Bridge bearer-token auth uses `crypto.timingSafeEqual`; request bodies are capped at 4MB (413) and malformed JSON returns 400 instead of a logged-as-unhandled 500.
- `requestApprovalDecision` clears its timeout timer, aborts the requester's `AbortSignal` on timeout, and no longer misclassifies a human deny whose reason is literally "approval timeout" as a system timeout.
- `semanticDrift` now reports tool calls present in only one of the two decision logs instead of silently ignoring calls that appear only in the replayed log.
- Worker-mode `allowedWritePathPrefixes` now fails closed when a write input yields no extractable paths (previously the vacuous `every()` allowed the write through).
- `loadPolicy` wraps malformed policy JSON in `E_SCHEMA_PARSE` (was a raw `SyntaxError`) and verifies HMAC signatures with a timing-safe comparison.
- Level-B/Level-C log loaders wrap malformed JSONL lines in `E_SCHEMA_PARSE` with file path and line number.
- `verifyTape` rejects empty tapes and tapes that do not start with a header record.
- `pi-harness replay` parses the tape once instead of twice (new `verifyTapeRecords` helper).
- `npm run lint` now has a repo-local TypeScript ESLint config instead of failing with missing-config / unmatched-pattern errors.
- `npm test` no longer runs the hash-chain microbench by default; the perf bench moved to opt-in `npm run bench`.

### Performance
- Bridge event ids come from a per-run counter instead of filtering or indexOf-scanning the whole event array per emit/broadcast, which made event emission O(n^2) over a run's lifetime.
- The bridge client backs off run polling from 50ms to a 500ms ceiling instead of hammering `/runs` at ~20 req/s for the whole run.
- `compactHistory` indexes compactable segments by event index (Map lookup) instead of a per-event linear scan.
- The query loop builds sofie tool evidence from two lookup maps instead of scanning the full event and effect arrays per policy decision.
- `read_events` finds the last event for an execution with a reverse index walk instead of copying and reversing the whole session event array on every wake-up.

### Changed
