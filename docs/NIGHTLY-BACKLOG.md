# Nightly backlog

Items the nightly maintenance pass surfaced but did not land, plus items it
checked and deliberately rejected. Keeping the rejections here stops later
runs from re-proposing work that was already considered.

Roadmap items live in `docs/ROADMAP.md`; this file is only for things the
nightly pass raised. Where an item is already tracked on the roadmap it is
referenced rather than duplicated.

## Open

- [ ] 2026-08-22 — Audit the remaining `catch { return [] }` evidence readers — the Sofie fixes below closed the two that flip a verdict, but `tryReadJson` (checkpoint) and `readProvenance(...).catch(() => null)` in `src/sofie/runtime.ts` still turn a damaged artifact into a silently absent one. Neither drives an escalation today, so neither is urgent; the question worth answering once rather than per-file is whether "unreadable" should be a distinct context state from "absent" across the whole `buildSofieContextFromSession` surface, instead of each reader deciding on its own.
- [ ] 2026-08-21 — Persist `accepted_at` on bridge run records — `GET /runs?limit=N` documents itself as tailing the most recent runs, but a restored run carries no acceptance timestamp, so after a restart the order is only a proxy (session `created_at`, then `execution_id`) rather than true acceptance order.
- [ ] 2026-08-21 — Decide the ESLint path — `eslint 8.57.1` has had no security patches since 2024-10-05, and 9.x reached EOL on 2026-08-06, so a 8→9 bump lands on an already-dead line. Only 10.x is supported; that is a flat-config migration, not a version bump.
- [ ] 2026-08-21 — Sort `metrics.json` keys before writing — `Counters.snapshot()` returns `Object.fromEntries` of a `Map`, so key order is first-increment order, and `safeWriteJson` uses `JSON.stringify` rather than `canonicalize`. Two runs with identical counters can produce byte-different artifacts.
- [ ] 2026-08-21 (2nd pass) — Persist `LoopResult.sanitizations` to its own artifact — the typed `SanitizationRecord`s now survive the loop, but only in memory. Every sibling record type has a durable sink (`effects.jsonl`, `policy.jsonl`), so a run's sanitization history still dies with the process and `verify`/`replay` cannot check it. Wants a `sanitizations.jsonl` alongside the others plus a `LoopInputs.sanitizationLogPath`. Held back from the applying commit to keep that change additive-only and leave the golden digest untouched.
- [ ] 2026-08-21 (2nd pass) — Design proposal: make the trust label on tool output checkable — `wrapToolOutput` carries `trusted="false"` and the tool identity as text *inside* the payload they describe, which `syntheses/synthesis-telephone-game-per-claim-confidence` names as the case where the invariant stops being checkable: a dropped tag is indistinguishable from one that was never added. Escaping and pre-dispatch policy enforcement mean this is defence in depth rather than the only defence, so it is not urgent. A real fix means carrying trust as a structured field on `ToolResultEvent` and having the adapter re-render it at the model boundary — that changes `StreamEventSchema`, so it changes every tape hash and forces a golden re-baseline. Architectural, not surgical; recorded here rather than attempted. See `docs/HARNESS-INVARIANTS.md` invariant 3.
- [ ] 2026-08-24 — Design proposal: give `KnowledgePathClass` one exhaustive authority table instead of five hand-maintained lists — `src/hermes/kbAccessPolicy.ts` has taken sixteen nightly fixes and the large majority are one bug: *a path class was omitted from one of the lists that decides authority*. There are five such lists, each enumerating a subset of the fifteen classes independently — the `if` chain in `assertKnowledgeWriteAllowed`, `PROMOTION_SOURCE_CLASSES`, `PROMOTION_TARGET_CLASSES`, `GOVERNED_DELETE_DENIED_CLASSES`, and a sixth copy in `preflightV2KnowledgePolicy` over in `httpBridge.ts`. Nothing relates them, so adding a class or a zone leaves five places that silently keep their old answer. `aa84ad3`, `311d5d0`, and `6740647` are each that same omission in a different list. A live instance remains: `kb_archive` is absent from `GOVERNED_DELETE_DENIED_CLASSES`, so `deleteKnowledgePath({ actor: "pi" })` unlinks a tombstone under `archive/rejected/` outright, while the byte-identical `trust: canonical` record written to `supervision/` is denied — and `createKnowledgeTombstone` only accepts those two zones, so the retirement record a governed delete points at is the deletable one. Deliberately **not** patched: patch seventeen of a class is the wrong move. The fix is to declare authority once as `Record<KnowledgePathClass, ZoneAuthority>` — writable-by, deletable-by, promotable-from/to, immutable, append-only, frontmatter-required — and derive all five decisions from it. A `Record` keyed by the union is exhaustively checked, so an omitted class becomes a `tsc` error instead of a finding for a later nightly. Sizeable but mechanical; it wants its own change because it touches every KB test.
- [ ] 2026-08-24 — The bridge accepts security constraints it silently drops — `PiHermesTaskEnvelopeV2Schema` validates a `constraints` block, and of its fields only `timeout_seconds` is enforced anywhere. `path_allowlist`, `path_denylist`, `network_access`, `max_steps`, `max_subprocess_depth`, `side_effect_class`, `requires_isolation`, `disallowed_tools`, and every `budget.*` field have zero references outside the schema that defines them; `write_access` and `allowed_tools` reach the worker only as an env var and a prompt line. That is defensible for a contract whose status is "Draft for implementation" — but `path_denylist` is documented as "absolute paths Hermes must not touch" and the canonical example in `PI_HERMES_CONTRACT_V2.md` §3.7 populates it with SSH and cloud-credential directories. An operator who copies that example gets a validated, accepted, entirely inert control and no signal that it did nothing. The cheap first step is not enforcement — it is honesty: have `preflightV2KnowledgePolicy` emit a preflight event (or refuse the envelope under a strict flag) when a populated constraint field has no enforcement path, so an inert control is visible in the run trace instead of silent.

## Closed

- [x] 2026-08-24 — A typo in a policy file widened the rule it appeared in instead of narrowing it — `PolicyMatchSchema`, `PolicyRuleSchema`, and `PolicyDocSchema` were all in zod's default `strip` mode, so an unrecognised key was dropped rather than rejected. `ruleMatches` treats an empty `match` as "matches everything", so dropping the only scope key off a rule did not disable the rule — it removed its scope. Reproduced on main: `match: { tool: "write_file", pathprefix: "tests/" }` parsed to `match: { tool: "write_file" }` and approved a `write_file` to `/etc/shadow`, and `match: { toolName: "read_file" }` parsed to `match: {}`, so an approve rule authored for one reader approved every tool call in the document. Only hand-authored policy JSON reaching `loadPolicy` is affected — in-repo `PolicyDoc` literals are type-checked, so the same typo there is already a compile error. Fixed on `nightly/2026-08-24-improvements` by making all three schemas `.strict()`; two regression cases in `tests/unit/policyEvaluator.test.ts` fail against the pre-fix source. Every committed policy fixture uses only known keys, so nothing existing had to change.
- [x] 2026-08-22 — Sofie read a crash-torn `policy.jsonl` as a session with no denials — `buildSofieContextFromSession` called `readPolicyLog` inside `catch { return [] }`, and that reader rejects the whole file on one unparseable line. With effects present the insufficient-evidence guard does not fire, so a session with a recorded `deny` returned `verdict: answer` / "review passes within bounded authority" instead of `caution`. Fixed on `nightly/2026-08-22-improvements` by adding `readPolicyLogLenient`; `readPolicyLog` keeps its strict contract for `inspect`/`replay`.
- [x] 2026-08-22 — Same fail-open on the effect log, with a worse blast radius — `tryReadEffects` dropped every `EffectRecord` on one torn line, and `effects` is what `detectDestructiveActionOutsidePolicy` inspects for writes into `.git`/`node_modules`. A session that wrote `.git/config` went from `escalate` / `destructive_outside_policy` / `needs-human` to `answer` / `complete`. Fixed alongside the above via `readEffectLogLenient`. Both now emit a `policyLogUnparsedLines=N` / `effectLogUnparsedLines=N` friction finding so a damaged log reads as damaged.
- [x] 2026-08-21 (2nd pass) — Sofie certified completion over a failed build — `answerRoutineQuestion` read `targetSummary.installOk/lintOk/buildOk` for presence but never for value, so a target whose lint and build both failed still returned `verdict: answer`, "review passes within bounded authority", and `closureRecommendation: complete`. Fixed on `nightly/2026-08-21-improvements`; see `docs/HARNESS-INVARIANTS.md` invariant 4.
- [x] 2026-08-21 (2nd pass) — `SanitizationRecord` had no producer — the loop computed the record and discarded it, making tool-output truncation and tag-escaping measurable only by regex-scraping the payload. `LoopResult.sanitizations` now carries it. Persisting it is still open, above.
- [x] 2026-08-21 (2nd pass) — `bridgeStateStore.test.ts` flaked ~1 run in 3 — ENOTEMPTY from the `afterEach` recursive rm racing APFS, not from any assertion. 5 failures in 15 runs before, 0 in 20 after adding `maxRetries`/`retryDelay`.

## Checked, not applicable

- 2026-08-24 — Applying `.strict()` to the rest of the zod surface — the policy fix above raised the obvious follow-up, and the answer is no, not as a sweep. `.strict()` was previously used nowhere in `src`, so turning it on everywhere would change the accept/reject behaviour of every persisted-artifact reader at once, including replay of tapes written by older versions. The policy schemas are the case that warrants it on its own merits, because they are the only ones where a dropped key *widens* authority rather than losing data: `ruleMatches` reads an absent constraint as "no constraint". The nearest analogue is `constraints.path_denylist` on the V2 task envelope, which also defaults to permissive — that is covered by the open item above, and it needs enforcement before strictness is worth anything.
- 2026-08-24 — `npm run check:secrets` outside a commit — the script reads `git diff --cached`, so running it on a clean tree scans nothing and exits 0. That is correct for what it is (the `.husky/pre-commit` guard for R11) and its own docstring says so, but it means a green `check:secrets` in a CI or nightly log is not evidence that the tree is clean. Reviewed the patterns rather than the invocation: path pass plus eleven self-identifying content prefixes, no entropy heuristics, and it correctly exempts only its own two fixture files from the content pass. Not a stub. A separate full-tree mode would be a new feature, not a fix, and `git grep` over tracked files covers the same ground for an auditor who wants it.
- 2026-08-24 — Frontmatter field values are unvalidated — `assertRequiredFrontmatter` checks the eight required fields for presence but never against the enums `KB_ACCESS_POLICY_V1.md` defines for them, so Hermes can write `trust: canonical` / `created_by: pi` into a queue zone. Traced every consumer: nothing in `src` reads `trust` or `status` off a KB artifact, so today the field is a label with no reader and constraining it would guard nothing. The one value that *is* consumed is `created_by`, which `promoteKnowledgeCandidate` copies from worker-controlled source frontmatter into the canonical record via `inferCreatedBy`. Even there the promoted artifact separately records `promoted_by: pi` and the full `source_paths`, so provenance stays reconstructable. Worth fixing when something starts making decisions on `trust`; not before.
- 2026-08-24 — Research sweep for this run turned up nothing new to record — Node 20 EOL, the ESLint 8/10 path, the MCP 2026-07-28 spec, retired model IDs, and the zod 3→4 drift were each already carried by the 08-21 through 08-23 passes (the model-ID and `.tool-versions` entries sit on the unmerged `nightly/2026-08-23-improvements` branch). Re-verified rather than re-proposed: no new advisories against the current pins, and `src` still selects no model at runtime.
- 2026-08-22 — Widening `pathsOf` beyond `path`/`paths` in `src/policy/engine.ts` — the obvious next step after the 2026-08-21 path-union fix would be to also collect `file_path`, `old_path`/`new_path`, `destination`, and friends. Counted across `src` and `tests`: 89 tool inputs use `path`, 1 uses `paths`, and no other spelling appears anywhere. Adding names for shapes this repo's tool contract does not have would be a second special case guarding nothing. If a tool ever lands with a different path field, the fix is a declared path-field list on the tool registration, not another `if` in `pathsOf`.
- 2026-08-22 — Missing `Host` header skips the rebinding check — `isTrustedRequestOrigin` only rejects a Host header that is present and non-loopback, so a request with no Host at all is treated as trusted. Not a bypass of anything: the check exists to stop browsers, and every browser sets `Host` on every request. A client that can omit it is already a local non-browser process, which the check was never a boundary against. Recorded so a later pass does not re-derive it as a finding.
- 2026-08-22 — Committed-credential sweep — scanned the full history (277 commits, all refs) for GitHub PAT/OAuth/App, npm, Slack, AWS, Google, and model-provider key formats plus inline private keys. (Quoting that begin-line literally here is itself enough to trip the guard, which is the correct behaviour and is why this entry describes it instead.)

- 2026-08-21 (2nd pass) — `resolveExecutable` PATH fallback — `src/hermes/transport.ts` resolves a bare command against `env.PATH ?? process.env.PATH`, so a caller who deliberately passed a `PATH`-less env to sandbox a child would get the binary located via the *harness's* PATH and then spawned with an env lacking it. Not reachable today: the only caller (`HermesAdapter`) always spreads `process.env`. Could not construct a failing case through a public entry point, so it is recorded as a finding rather than fixed. See `docs/HARNESS-INVARIANTS.md`.

Not landed unilaterally.
